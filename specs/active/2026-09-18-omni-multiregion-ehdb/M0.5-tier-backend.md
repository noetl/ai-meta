# M0.5 — Tier-store backend dispatch (L0 convergence)

Phase of [`spec.md`](spec.md). **Planning only.**
**Prerequisite for M1, M4, M7.** This is stage 3 from
[`TRACE-RESULTS.md`](../../../loops/active/2026-09-11-ehdb-resilient-core-phases/handover/TRACE-RESULTS.md),
consumed here rather than duplicated.

## Scope

Give `tier_store::driver()` a backend dispatch so the `primary`-serving
event-log tier can be served by an L0-backed driver instead of only by
`LocalReferenceEventLogDriver`.

## Why this phase exists — the §0 correction

**VERIFIED:**

- `worker/src/ehdb/tier_store.rs:207` — `fn driver(..) -> LocalReferenceEventLogDriver`,
  a **concrete return type with no match**.
- `ehdb/crates/ehdb-reference/src/eventlog.rs:339` — that driver *"composes the
  existing append-only stream primitives (`LocalReferenceRuntime` +
  `ehdb_stream`)"*.
- `ehdb-reference/Cargo.toml` `[dependencies]` contains **no `ehdb-l0`**.
- `ehdb-stream/Cargo.toml` `[dependencies]` = `ehdb-core`, `serde`,
  `serde_json`. Storage is `OpenOptions::new().append(true)` +
  `BufReader::lines()`. Occurrence counts in its `lib.rs`: `replica` **0**,
  `seal` **0**, `manifest` **0**, `fsync` **0**, `sync_data` 1.
- `worker/src/event_bus.rs:258` opens `L0Engine::<D1EventLog>::open(...)`, and
  the tier service is spawned from the same file (`:321` config,
  `:358 serve_tier`) — **same process, different storage stack, different
  port**.

⇒ Every L0 primitive the later phases extend is **not on the tier's path**.
Without M0.5, M1/M4/M7 are inert on the tier for the same reason
`NOETL_EHDB_EVENTLOG_BACKEND` is inert (plan §1.2).

## Interfaces / data shapes

No new wire type. `EventLogAppendOutcome` is **unchanged** — and must stay so,
because it crosses a process boundary (tier service serialises, worker parses)
and its `deny_unknown_fields` was already removed for exactly this reason
(**VERIFIED**, `ehdb-reference/src/eventlog.rs:142`).

⚠ The two backends have **different sequence semantics**. `ehdb-stream`'s
`StreamSequence` starts at 1 and refuses 0 (**VERIFIED**,
`ehdb-stream/src/lib.rs:18-25`); L0's `global_sequence` is recovered as
`manifest.max_sequence()` (**VERIFIED**, `engine.rs:405`). A backend switch on a
non-empty store is therefore **not** a no-op and is out of scope: M0.5 ships the
dispatch, not a data migration.

## Entry criteria

- [ ] M0 exit.

## Exit criteria

- [ ] E1 — `driver()` dispatches on the flag.
- [ ] E2 — Under `local_reference`, the produced bytes **and** the
      `EventLogAppendOutcome` are byte-identical to today, over a fixed
      population of ≥ N appends. Publish N.
- [ ] E3 — Under `l0`, append/read/scan/tail/ack round-trip in kind.
- [ ] E4 — A store written by one backend is **refused** by the other, not
      silently misparsed. This is the criterion that matters most: a silent
      misparse on a `primary` tier is a wrong answer, not an outage.
- [ ] E5 — `ehdb_tier_backend_info{backend}` gauge, always 1, **pinned for both
      label values** so a scrape says which backend is running. (Rationale: the
      program has already answered "does this pod predate that metric?" from a
      Deployment image tag — a different representation that can disagree with
      what is running.)

## Proof / verification

| # | Planted defect | Must go RED in |

| 1 | dispatch ignores the flag and always returns `local_reference` | the `l0` round-trip test |
| 2 | dispatch ignores the flag and always returns `l0` | the byte-identity test (E2) |
| 3 | cross-backend read returns `Ok` with a garbled record instead of `Err` | the E4 refusal test |
| 4 | unrecognised flag value falls through to `l0` | the fail-safe test |
| 5 | **Positive control** — the byte-identity test is run against a store with one deliberately differing record | must go RED; if it stays green the differential is not comparing what it claims |

⛔ Forbidden instruments: cross-store parity comparator;
`/api/ehdb/projection-fold/diff/{id}`.

## Blast radius

⚠ **Highest before M5.** This changes the store under a tier that is `primary`
in production. Two specific hazards, both already recorded:

- ⚠ **Rolling `cmdbus-writer` loses in-flight executions** — commands submitted
  during its restart window return an `execution_id` and produce zero events
  (seen three times; **VERIFIED** in the handover). Drain or quiesce first.
- ⚠ A roll on a 1-replica pool at high node memory must be **surge-free**;
  `maxSurge=25%` there means +1 pod.

## Rollback

Flag → `local_reference`, redeploy. No data written under `l0` in prod, because
promotion past the default is owner-gated and out of scope here.

## Open questions (non-blocking)

- Whether the tier ever migrates *data* onto L0, or runs `l0` only for new
  shards. Recommended: **new shards only**; a live migration of a `primary` tier
  is a separate spec with its own rollback story.
