### Things that will bite a fresh session

- ⚠⚠ **The backfill is NOT `register`.** Re-posting existing rows through
  `/api/catalog/register` runs `MAX(version)+1` and creates a second version of
  every one of the 2,528 entries — describing the catalog by doubling it.
  `POST /api/catalog-log/backfill` emits the row's **existing** version and never
  touches `noetl.catalog`.
- ⚠⚠ **A whole-log scan cannot work.** The tier-service frame caps at **1 MiB**;
  the catalog log measured **6,553,796 bytes**. It 502s rather than truncating.
  The fold pages **adaptively** — one entry can be 267 KB, so a page of 25
  measured 1.3 MB; on a frame-cap refusal the page halves.
- ⚠ **The first page must omit `after`** — the store rejects `after=0` with
  *"stream sequence must be greater than zero"*. Starting from the beginning is
  the *absence* of a cursor.
- ⚠ **`playbook.initialized` is never emitted** despite five readers. The real
  start event is `playbook_started`.
- ⚠ **Catalog registration was not event-sourced** before step 2 — `register` is
  a direct `INSERT`. That is why the relation had nothing to fold.
- ⚠ Catalog records must **not** go in the eventlog tier: they have no
  `noetl.event` row, so the parity comparator would fire `extra_event`, which
  **pages**.

### 🔴 What the specs found — these are LIVE gaps, not future ones

The event-log tier has been **`primary` and serving on prod since 2026-08-13**.
Both specs first said "no tier goes primary until this merges"; **that was false
as written** and is corrected in each. The gaps below therefore apply to a tier
already in production.

1. **⚠⚠ Single-writer-per-shard is enforced by nothing.** No epoch, fencing
   token, lease or election exists anywhere in the ehdb tree. It rests on
   `StatefulSet replicas: 1` — an orchestration preference, not mutual
   exclusion. A partitioned node shows `Terminating` while it keeps appending.
2. **⚠⚠ The storage contract refuses nothing.** `put_segment` overwrites
   unconditionally; `append_delta` appends at a `committed_len` the *caller*
   supplies. A fencing token in the frame is **inert unless the store rejects on
   it** — that is why the spec puts the check in the storage contract, not the
   writer.
3. **⚠⚠ The durability window is unbounded in time.** `should_seal()` triggers
   on 8 MiB or 1024 records with **no age trigger**, and only sealed parts
   upload. Idle shards never replicate. *The system is least durable where it is
   least active* — the opposite of the intuition anyone brings.
4. **⚠⚠ The only metric naming lag cannot see it.** `upload_lag_micros_total`
   measures from `sealed_at`, so unsealed records contribute zero.
   `ehdb_feed_shard_lag` is **consumer backlog**, not replication lag — and it
   is the name an alert author reaches for first.
5. **⚠⚠ In prod the "durable substrate" is the same PVC.**
   `NOETL_EHDB_TIER_SERVICE_DIR=/data/eventbus/ehdb-tier` sits inside
   `NOETL_EVENT_BUS_WRITER_DIR=/data/eventbus`. `LocalFsSubstrate` is the only
   substrate implementation in the tree. Replication buys **no independent
   failure domain**, and RF > 1 is blocked on there being a second substrate to
   replicate *to* — not merely on a `replicas` list.
6. **⚠ Only two tiers can serve.** `SERVE_WIRED_TIERS = ["eventlog",
   "projection"]`. The wiki's five-tier `off/shadow/primary` table reads as
   though `NOETL_EHDB_KV=primary` promotes something. It does not. Home now
   says so above the fold.
7. **⚠ The prod writer does not run L0's documented default** —
   `FlushPolicy::CallerDriven`, one `fsync` per batch (group commit). Ack
   durability unchanged, but the crate docs mislead.

### Things a fresh session should not re-derive

  the worker's literal construction at `command_bus.rs:372` on repin. F4 exports

- ⚠ **The epoch cannot ride the segment frame.** `FRAME_HEADER_LEN` is a fixed

- ⚠ **`get_range` past an object's end is now a hard error**, everywhere. A

- ⚠ **A decorator must forward `failure_domain()`**; the default would silently
  downgrade a real substrate to `Undeclared`.
- ⚠ **CI here runs `cargo fmt --all --check` and `clippy -D warnings`.** A

## 8. Verification habits that earned their keep

- A check that has only ever passed is indistinguishable from one that cannot
  fail. **Run the positive control.**
- `absent ≠ zero`: pin metric label sets, or a missing series reads as healthy.
- Read the **original**, not the copy — prod state from the cluster, resolved deps
  from the lockfile, event types from a live execution.
- Mutation-test every guard: break it, watch it fail, restore it.
