# Prod server v3.156.2 → v3.161.2: a cancelled execution's commands are refused the claim
- Timestamp: 2026-11-13T03:00:00Z
- Author: Kadyapam
- Tags: server, prod, cancel, claim, orphan-sweep, rollout, ops

## Summary

The cancel API writes `playbook_cancelled`, but three readers checked other spellings, so a queued command stayed claimable after a cancel. The fixes are server#581 (claim, v3.161.1) and #583 (status lookup + orphan sweep, v3.161.2), and all three readers now use one shared `CANCELLED_EVENT_TYPES` list. v3.161.2 was rolled to prod at 2026-11-13T02:50:48Z.

## Actions

- **Roll:** image-only JSON patch by digest, guarded by a test op on the old digest; the server-side dry-run diff was the image line only. Rollback pin: v3.156.2 `sha256:1433c32191277c66eae87ccf88b9e708d6c98cf38420f0f14f2b3b620efcec44`.
- **The range carried v3.157–v3.161:** catalog features, all flags unset on prod, no schema change. The env names prod sets were checked unchanged.
- **Smoke, before → after:**
  - e2e 7/7 → 7/7 COMPLETED.
  - Cancel probe: `Command already claimed by …` → `Execution has been cancelled`.
- **Manifest:** ops#380 pins the live digest (it had named `7c0b999d`), and the ledger gains two rows.

## Lessons

- **A cancel test must probe the claim on a command that is still running.** In prod a real worker claims within seconds. `claim_command` checks for cancellation before it checks ownership, so the probe answer tells the two servers apart: the fix says "cancelled", the old server says "already claimed".
- **Under `NOETL_EVENT_INGEST_PUBLISH_ONLY`, the cancel row reaches `noetl.event` through the materializer**, so poll the probe rather than assert once.
- **Read the running digest and its tag before assuming the rollback target.** Prod was on v3.156.2, not v3.161.0, so the roll carried five releases.
- **Never run `cargo fmt --all` in noetl/server.** The repo is not rustfmt-clean, and source-text tests (`auth_gate_wiring`) break on a reformatted `main.rs`.
