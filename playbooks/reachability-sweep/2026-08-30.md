# Reachability sweep — 2026-08-30

Every feature merged in this run, checked for whether anything **calls** it.
Existence is what a naive grep measures; reachability is the property that
matters, and the two came apart four times here.

## Method, and its two false-zero traps

Counted non-comment, non-test call sites per symbol across `ehdb/crates`,
`worker/src`, `server/src`, then **read every non-zero hit** to distinguish a
call from a `pub use` re-export.

⚠ **Trap 1 — the control must exercise the calling convention.** The first run
returned `0` for *everything*, including two symbols I had wired myself. Cause:
the roots were passed as an unquoted zsh variable, and **zsh does not
word-split**, so all three arrived as one non-existent directory. The positive
control passed because it used literal paths — *it did not exercise the same code
path as the real run*, so it certified a broken tool.

⚠ **Trap 2 — excluding the defining file hides intra-module wiring.**
`events_for_recovery` scored `0` while being demonstrably live on prod. Its three
callers are inside its own module, which the tool skipped. A module's entry point
is often in the same file as the thing it calls.

Both were caught by disagreement with known reality, not by the tool.

## ⚠⚠ What the DEAD rows cost

Three of the five remediation features are unreachable, and each one silently
voids a gate's precondition:

- **F1 (election)** — G3 cannot begin. Also blocks G2: enforcing while every
  epoch is `0` is an outage, so fencing enforcement *needs* real tokens.
- **F3 (age seal)** — G1b's flag is not even read into the engine config, so
  setting `NOETL_EHDB_SEAL_MAX_AGE` on prod today would do **nothing at all**,
  silently.
- **F5 (domain validation)** — G4's verify-before ("`check_replica_domains`
  reports no violations against the live paths") cannot be evaluated, because
  nothing computes it against the live paths.

**A gate whose precondition cannot be evaluated is not a gate.** That is the same
shape as the fencing counter finding, three more times.

## Disposition

None is obsolete; all three are staged work whose wiring was never done.

| feature | disposition |
| :-- | :-- |
| **F5 domain validation** | **Wire as an observation** — compute domains at open, emit a gauge, enforce nothing. Answers "would prod fail G4?" *from the running system*. Highest value, fully inert. |
| **F3 age seal** | **Plumb the config knob** (`NOETL_EHDB_SEAL_MAX_AGE` → `L0Config`), default-off, plus a gauge saying whether it is configured. ⚠ The **timer** that drives `seal_aged_parts()` stays gated — it touches the live writer loop. |
| **F1 election** | ⚠ **Cannot be honestly wired**: the K8s `LeaseStore` adapter needs an HTTP/`kube` dependency decision that is the owner's. Wiring it against the in-memory store would produce a counter that means nothing. Disposition: **emit `ehdb_election_active 0`** so the dead state is *observable* rather than silent, and flag the dependency. |

Nothing is proposed for removal.

## What changed, and what did not

- **F3 was worse than unwired.** `L0Config::seal_max_age` existed and was never
  read from the environment, so **setting `NOETL_EHDB_SEAL_MAX_AGE` on prod would
  have silently done nothing** — G1b would have looked taken. Now plumbed
  (`NOETL_EHDB_SEAL_MAX_AGE_MS`), default-off. ⚠ The **timer** for idle shards is
  still gated.
- **F5 now answers G4's verify-before from the running system** rather than from
  manifests. Observation only — prod violates the check today, so enforcing would
  be a startup outage by construction.
- **F1 is still dead, deliberately.** Its K8s adapter needs an HTTP/`kube`
  dependency decision that is the owner's; wiring it against the in-memory store
  would publish a token nothing honours. Its dead state is now *legible on the
  scrape* instead of requiring a grep, and a guard fails the build if it ever
  gains a call site so the hard-coded `0` cannot outlive the condition.

## ⚠⚠ Three self-referential guard bugs, worth naming

The guard that checks "is the election still unwired" took **three attempts**,
and the first two matched **their own source**: `include_str!` yields the whole
file including the test module, so it found the bare symbol name, and then found
the very needle literals written to avoid that. It now scans only the portion
before `#[cfg(test)]`.

⚠ And its positive control needed redoing: the first injected probe **did not
compile**, so the test binary never built and the "the guard fires" check
silently proved nothing. A control must be verified to build before its result
is believed.

Together with the zsh word-split and defining-file traps at the top, that is
**five distinct ways this sweep produced or nearly produced a confident wrong
answer** — every one of them a false *negative*, i.e. the reassuring direction.
