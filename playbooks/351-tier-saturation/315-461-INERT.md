## Why

#461 moved the give-up **record** out of the evictable orch_cache slot. It left
the **budget** inside (`ExecOrchState::consecutive_reconcile_noops`), and there
are **six** `orch_cache.evict` sites. Each resets it to zero, so it never
reaches 225 → give-up never fires → the tombstone is never marked.

**I fixed the record-keeping, not the thing that prevents the count from
accumulating.** Half the defect, shipped with a green battery, because every
test I wrote held the slot alive across the whole decay.

## ⚠ A hypothesis I formed and killed

That `advanced = n > 0` counted *"a command was dispatched"* as progress, which
would reset the budget every poll. Its log line — *"reconcile poller advanced a
stuck execution"* — appears **0 times in 6,000 lines**. `advanced` is correctly
`false`. Had I reported that without checking, the follow-up fix would have
targeted the wrong line.

## Two readings corrected along the way

- ⚠ The 52 → 16 `in_flight` drop right after the deploy was the **restart
  emptying an in-memory cache**, not the fix — every counter reset with it

- ⚠ **91 of 100 executions carry a non-null `completed_at` while `status` reads
  `RUNNING`** — the frozen Python-era column (ai-meta#235). The earlier "36
  RUNNING for 6–28 h" framing was partly reading a dead column. Executions do

  run finished at 00:37, *before* the 05:07 deploy, so it is not evidence for
  #461 either.

## The completion — PR noetl/server#462, NOT merged

Budget moves into `DriveTombstones` (which already survives eviction), freed
when the tombstone is set so it stays bounded, and
`consecutive_reconcile_noops` **removed** from `ExecOrchState` so it cannot be
silently reintroduced.

The test I should have written first:
`decay_survives_orch_cache_eviction_on_every_poll` evicts the slot on **every
poll** — what production does — and still requires decay in exactly `CAP` polls.
**Arm E1 reproduces the half-fix exactly and FAILS**, so the test discriminates
the shipped code from the correct code. 1138 tests green with `--all-targets`.

## The general lesson

Both defects, and my half-fix, are one shape: **state that decides a loop's
termination must not live in a structure the loop evicts.** I moved one such
field and left its twin behind, and no test caught it because every fixture I
wrote kept the slot alive. The fixture has to do what production does — here,
evict on every poll.
